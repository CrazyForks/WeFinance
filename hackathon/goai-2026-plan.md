## 1. 为什么是 WeFinance，不是 MeetSpot

GOAI 无界应用赛道手册 FAQ Q1 原文（权威表述，不是营销摘要）：

> "原则上建议参赛团队从五大赛题中选择一个方向参赛。团队也可在赛题范围内自拟更细分的真实场景，但**应能够归入对应行业方向，并说明与赛题的关联**。"

五大方向：AI+眼镜、AI+汽车、AI+金融、AI+教育、AI+工业制造。这条规则比"方向不限制创意边界"这句常被引用的半句话严格得多——自拟场景必须能归入五个方向之一，不能凭空开第六类。

评估过程（2026-08-08 完整过一遍）：
- **MeetSpot**（公平会面点推荐，523 star）——不自然归入任何一个方向。最接近的救场角度是 AI+汽车"长途出行规划"（手册 4.3.2 提到"同行人需求"），但需要从零写路线规划/服务区 POI 逻辑，且本质仍是"本地生活服务"而非车主场景。
- **检查了全部 96 个 calderbuild 仓库**（第一轮只看了 limit 30 最近活跃的 22 个，漏了 66 个，第二轮补全）。真正贴合的只有两个：
  - **EduSpark**（AI+教育）：功能清单几乎逐条对上手册的教育 Agent 子类型，但最后一次 push 是 2025-07-16（13 个月前），自带的 `PROJECT_STATUS.md` 承认线上跑的是"简化版"后端，完整版需要数据库但从没搭起来——功能可能大部分是文档里写了但代码没做完。
  - **WeFinance**（AI+金融，128 star，仅次于 MeetSpot）：账单图片→结构化数据（GPT-4o Vision，声称 100% 识别率 vs 传统 OCR 的 0%）、`services/langchain_agent.py` 是真实的 LangChain Agent（不是套壳 API 调用）、`vision_ocr_service.py`/`recommendation_service.py`/`structuring_service.py` 三层服务拆分、可解释投资推荐（推理链可见）、异常消费检测。最后 push 2026-01-22，43 页 commit 历史，工程成熟度接近 MeetSpot 本身（有 CLAUDE.md/AGENTS.md/devcontainer/i18n/deploy 文档）。

**结论：WeFinance。** 手册对 AI+金融的定位原文是"面向企业经营与风险研判的金融服务 Agent"，例子包括"中小企业经营画像"——WeFinance 现状是"个人"记账，需要往"个体户/小微企业主经营画像"方向做真实延伸（不是改个文案），细节见第 3 节。

**关键区别（容易被忽略）**：初赛只需简介+PPT，不强制可运行代码（手册 5.1）。复赛开始才强制要求可运行 Demo 和代码仓库。这意味着 8/16 前的窗口可以先把叙事和材料做扎实，真正的工程改造有到 9/3 的时间，不用在 8 天内赶工。

**奖金**：冠军 50万，亚军 30万，季军 10万，开源新锐奖(4-10名) 5000元/队，开源影响力奖(11-15名) 3000元/队，优胜奖(入围复赛) 500元/队，参与奖(有效提交) 纪念T恤。全场大奖 100万（评选口径偏向基础设施类项目，应用类项目拿到概率低，不作为目标）。

**评审权重**（手册 10.1）：行业场景价值25%、Agent能力与任务闭环25%、产品体验与Demo完成度20%、技术实现深度15%、安全合规与可追溯10%、开放/复用贡献5%。

**AI+金融专项评审**（手册 10.2）："重点看资料理解、依据追溯、风险提示、合规意识和避免越权决策"。

**AI+金融边界要求**（手册 8.1/9.3，红线级）：
- 不得直接提供确定性投资建议、信贷审批结论、保险赔付结论，不得替代金融机构决策
- 必须做数据合规说明：数据来源、授权方式、脱敏处理、隐私保护措施

**红线（手册 11，取消成绩级别）**：
- 仅概念说明/PPT无法验证 → 淘汰（WeFinance 有真实代码+历史 commit，不适用）
- 决赛展示与复赛承诺不符、未披露已有项目基础 → 取消成绩（**必须在材料里写清楚"原有基础 + 本次新增贡献"，这条 MeetSpot 材料里已经验证过写法，照抄结构**）
- 是否允许基于已有项目继续开发：**允许**，但需说明原项目来源、团队贡献范围、新增创新点（手册第9节表格原文）

## 3. 定位与真实需要新增的工作（不是文案改写）

**新定位**：WeFinance 从"个人记账助手"扩展为"个体户/小微企业主经营画像 Agent"——目标用户从"个人"扩展到"独立开发者、自由职业者、个体工商户"这类没有专职会计、靠手工记账管理经营流水的人群。核心工作流不变（拍照上传票据 → Vision LLM 结构化提取 → 分类 → 异常检测 → 可解释建议），但输出视图从"个人消费分析"延伸到"经营流水画像"（收入/支出趋势、客户回款周期、经营异常预警）。

这个定位选择的依据：手册 AI+金融一句话定位是"面向企业经营与风险研判"，例子"中小企业经营画像"是五个例子里唯一能被 WeFinance 现有技术栈（票据OCR+结构化+异常检测+可解释建议）直接复用、不用重新搭建的一个。

**真正要做的新增工作**（区别于 MeetSpot 那版计划的"重写叙事就行"，这次评审专项明确要求"资料理解、依据追溯"，必须有真代码）：
1. 经营流水视图：在现有 `pages/` 里新增一个"经营画像"聚合视图，把已有票据结构化数据按经营周期（而非个人月度账单周期）重新聚合展示——复用 `structuring_service.py` 的输出，不用重新做 OCR
2. 数据合规说明文档（手册硬性要求）：票据图片属于什么类型数据、是否包含个人敏感信息（收款人姓名/账号可能出现在票据上）、如何脱敏、是否本地处理还是调用 GPT-4o Vision 云端 API（后者需要披露）
3. 边界声明：在建议输出里加"不构成投资/信贷/保险决策依据"的免责声明（手册红线要求，目前 `recommendation_service.py` 是否已有需要核实）
4. Agent 任务闭环证据：`langchain_agent.py` 现有的工具调用链需要整理成手册要求的"任务输入→意图理解→任务规划→能力调用→结果交付→验证反馈"六步可视化说明（手册 8.2），这是"Agent能力与任务闭环"25%权重的直接得分点

## 5. 与 Anna Builder Program 的关系（重要：两件独立的事，不要混）

`annaresearch.md`（同目录）记录了一个完全不同的机会：把 WeFinance 的三个服务包装成 Anna AI OS 平台的 App，靠真实 MAU 拿月度资助（$50-$5000/月不等）。这条线的时间窗口（9月 Launch Boost）和技术路径（JSON-RPC stdio Executa Tool）与 GOAI 提交没有交集，两者共享同一份 WeFinance 底层代码，但面向不同平台、不同评审方、不同截止日期。执行时注意别把两边的任务、文档、术语混在一起——GOAI 材料不要出现"Executa/Anna App"这类词，Anna 那边的产品页也不要提"GOAI/无界应用"。
