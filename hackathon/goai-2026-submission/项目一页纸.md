## 项目名称

WeFinance 智能记账与经营流水助手

## 选择赛题与目标场景

无界应用（Boundless Agents）｜AI+金融赛道，对应手册 4.3.3 官方场景清单第一项"中小企业经营画像 Agent：生成经营画像、风险提示和服务建议"。目标场景细化为：个体户和自由职业者的票据理解 + 经营流水画像，是"中小企业经营画像"在最小可运营主体（个人经营者）上的落地。

## 目标用户与核心问题

个体户、自由职业者、习惯手工记账的普通用户。核心问题：记账依赖手工录入、票据识别准确率低；消费异常难以及时发现；理财建议千篇一律、不基于用户真实数据；缺少一个"经营者视角"回看自己流水的入口（现有记账工具只按"消费类别"分析，不按"交易对手集中度"这类经营指标分析）。

## 方案概述与核心流程

拍照上传账单 → GPT-4o Vision 一步完成结构化提取（日期/商户/类别/金额）→ 异常检测（z-score 统计方法，按样本量自适应调阈值）→ 消费洞察（按类别/时间趋势聚合）→ 经营流水画像（本次新增，按交易对手集中度、收支趋势、异常预警聚合，供个体户/自由职业者查看经营视角）→ 对话式财务顾问（多轮问答）→ 可解释理财分析报告（附推理链，不含确定性投资指令）。

## Agent 架构与关键能力

- 意图理解与任务规划：`services/langchain_agent.py` 基于 LangChain AgentExecutor，识别查预算、查分类、查具体类目等意图，结合对话记忆支持多轮交互
- 能力调用：`query_budget`、`query_spending`、`query_category` 三类工具；Vision OCR 与理财报告生成走独立服务层（`services/vision_ocr_service.py`、`services/recommendation_service.py`）
- 结果交付：结构化交易记录、异常预警卡片、经营画像聚合视图、附推理步骤（rationale_steps）的理财报告
- 验证与反馈：异常检测支持用户"确认/标记误报"反馈闭环（`trusted_merchants` 白名单机制）
- 安全边界：理财报告 prompt 明确限定"分析与教育性内容"，不点名具体产品/平台，不给确定性执行指令（详见下文安全合规边界）

## 数据来源、工具调用与技术路线

- 数据来源：用户上传的账单/收据图片（无第三方数据源）、用户输入的预算和聊天文本
- 模型服务：OpenAI 兼容接口（默认 `newapi.deepwisdom.ai`，模型 `gpt-4o`），`OPENAI_BASE_URL`/`OPENAI_MODEL` 可替换为任意 OpenAI 兼容端点
- 技术栈：Streamlit + LangChain/langchain-openai + Pydantic + Plotly + Pandas
- 全部 LLM 调用通过 `@safe_call` 装饰器提供超时保护（Vision 30s、Chat/建议 15s）和优雅降级

## Demo 运行结果

**本地实测（2026-08-08，已通过）**：本地启动 `streamlit run app.py`，加载种子交易数据后完整走通消费洞察、经营流水画像新视图（收支趋势图、交易对手集中度表格、异常预警）三个模块，展示数字随交易数据变化，非写死样例；过程中发现并修复两个真实缺陷（见下）。截图见 `assets/demo-business-profile-top.jpg`、`assets/demo-business-profile-detail.jpg`。

**线上实测（2026-08-08，未通过，如实披露）**：`https://wefinance-copilot.streamlit.app` 当前因 `ModuleNotFoundError: No module named 'openai'` 无法加载任何页面。经排查为 Streamlit Community Cloud 平台侧 Python 环境解析问题（2026 年社区已知的 `runtime.txt` 被忽略问题），需登录 Streamlit Cloud Dashboard 重新部署，非仓库代码可单方面修复。**材料措辞如实标注为"本地实测通过，线上部署修复中"**，不采用"线上稳定运行"的表述。

**本次实测顺带发现并修复的真实工程问题**（非虚构的"新增贡献"证据）：
1. `services/recommendation_service.py::generate_detailed_report` 的 prompt 曾要求 LLM 指名具体基金/平台并给出确定性买卖指令，违反手册 9.3 行业边界红线，已改写为"分析框架 + 用户自行核实"口径
2. `utils/ui_components.py` 的 Streamlit 新旧 `width` 参数兼容逻辑存在优先级缺陷，在 Streamlit 1.38.0 下会导致所有 `st.dataframe` 表格崩溃（`TypeError`），已修复并验证
3. 本地开发环境中 pip 装的 pyarrow 与 conda 的 numpy 存在 ABI 不兼容，触发真实的原生层 SIGSEGV 崩溃（非 Python 异常），已通过 conda-forge 重装 pyarrow 修复并验证

## 安全合规边界

理财建议系统提示词明确声明"分析与教育性内容，不构成投资/信贷/保险决策依据，不替代持牌金融机构判断"；不点名具体基金、券商或投资平台；不将执行参数（金额/时点/价位）当作确定性指令下达。异常检测、消费分析基于用户真实数据，不做身份核验，不采集身份证号/银行卡号等敏感字段。账单图片仅内存中处理，不落盘保存原图。详见 `数据合规说明.md`。

## 开放/复用贡献

MIT 协议开源，中英双语 README 和界面文案；票据识别、异常检测、推荐引擎均为独立服务层（`services/`），可拆分复用于其他记账类应用；GitHub 128 星、16 fork（2026-08-08 实测数据）。
