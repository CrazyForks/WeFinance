## 通用技术要求（手册 8.1-8.6）

- **面向真实场景**：目标用户为个体户/自由职业者，核心问题为票据识别、异常检测、经营流水画像，均有对应代码落点
- **Agent 能力**：意图理解 + 任务规划 + 工具调用 + 多轮交互见 `services/langchain_agent.py`
- **任务闭环**：账单上传 -> OCR 结构化 -> 消费分析/经营画像 -> 对话顾问 -> 理财建议，完整链路本地实测通过
- **可演示性**：本地 Demo 截图已留存；线上全链路已实测通过（2026-08-11，4/4 交易正确识别）
- **数据来源清晰**：见 `数据合规说明.md` 第三方依赖披露表
- **边界表达清楚**（对应 9.3 行业边界"金融类作品不得替代金融机构的投资判断"）：`generate_detailed_report` prompt 已改写，不再要求 LLM 指名具体基金/平台或给出确定性执行指令
- **记忆/上下文机制**（8.4）：对话顾问按 `ChatManager.get_context(limit=10)` 维护最近 10 轮消息作为上下文，不做跨会话长期记忆；跨会话保留仅限用户主动开启的 `utils/storage.py` 本地持久化（预算、信任商户名单），不持久化聊天记录本身
- **数据脱敏/权限控制/删除机制**（8.4）：账单图片仅内存处理不落盘；本地持久化数据（`~/.wefinance/data.json`）为未加密 JSON，无网络暴露；应用侧提供真实可用的一键清除入口（`app.py` 侧栏"🗑️"按钮，二次确认后调用 `clear_all_storage()` 清空本地文件与当前会话状态），非文档承诺
- **外部工具/API 调用权限范围**（8.5）：唯一外部依赖是用户在 Streamlit Cloud Secrets 或本地 `.env` 中配置的 OpenAI 兼容 API key（默认端点 `newapi.deepwisdom.ai`），该 key 仅被用于三类只读+生成式调用（Vision OCR 结构化提取、对话补全、理财报告生成），不具备写入用户账户、发起交易或访问除对话内容外其他数据的权限；LangChain AgentExecutor 的工具集固定为 `query_budget`/`query_spending`/`query_category` 三个只读本地函数，不接入外部系统

## 已知缺口（如实披露，不隐瞒）

1. **`tests/` 测试目录当前不存在**：手册 5.1 明确初赛不强制可运行代码/测试，复赛前（手册 6.2 要求"测试方法、运行证据"）需要补齐。
2. **`generate_detailed_report` 生成耗时较长**：完整理财报告约 4000-6000 字，实测生成时间受限于 LLM 响应速度，需在复赛 Demo 中标注预期等待时间（当前超时保护为 60 秒）。

**已修复的缺口（不再是缺口，记录修复过程作为工程严谨性证据）**：
- ~~线上 OCR/理财建议等 LLM 调用曾返回 403~~：Streamlit Cloud 部署问题（Python 版本配置）已于 2026-08-09 修复并重新验证，页面全部正常加载；随后用真实样例账单实测上传，日志显示 `openai.PermissionDeniedError: Error code: 403`，起初判断是 Secrets 中 API key 被服务商拒绝（`{'code': 300...}`），换新 key 后 403 依旧。进一步排查发现真实根因是服务商（SiliconFlow）已将当时配置的模型 `Qwen/Qwen2-VL-72B-Instruct` 下线（控制台显示为 Deprecated，返回 `{'code': 30003, 'message': 'Model disabled'}`），与 API key 是否有效无关。切换至当前活跃的 `Qwen/Qwen3-VL-32B-Instruct` 后，2026-08-11 线上真实上传样例账单复测，4/4 笔交易全部正确识别（商户/日期/金额/分类）。失败路径本身在修复前也表现符合预期：`@safe_call` 捕获异常，前端友好提示"账单识别失败，请刷新页面重试"，未导致整个应用崩溃，`assets/demo-live-ocr-403-evidence.jpg` 保留作为修复前真实故障现场与失败可解释性的证据。
- ~~`pages/bill_upload.py` 财务健康卡片渲染为纯文本~~：根因是 `render_financial_health_card`（`utils/ui_components.py`）拼接的 HTML 字符串内含空行，`st.markdown` 底层走 CommonMark 规则，HTML block 遇空行提前终止、后续标签被转义为纯文本。该组件被 4 个页面（账单上传/消费分析/AI顾问/投资建议）共用，修复后全部页面同时生效。2026-08-09 修复并在本地两个页面截图复核。
- ~~本地/线上运行日志反复打印 `Failed to load storage file: Expecting value` 警告~~：根因是 `utils/storage.py::_resolve_storage_file` 用"以追加模式打开再立即关闭"探测目录可写性，会在首次运行时留下一个 0 字节的空文件；`_load_all` 随后每次读取都对这个空文件调用 `json.load`，触发 JSON 解析异常并记警告日志，在同一会话内的每次 rerun 都重复出现（`assets/demo-live-ocr-403-evidence.jpg` 截图里可见约 20+ 次重复）。已修复为读取前先判断内容是否为空白，空文件视为合法的"尚无数据"状态，不再报警告。2026-08-09 修复。
- ~~`environment.yml` 与 `requirements.txt` 存在 Streamlit 版本差异~~：`environment.yml` 的 pip 段落曾固定 `streamlit==1.28.0`，与 `requirements.txt` 的 `streamlit>=1.37,<2.0` 及本地实测使用的 1.38.0 不一致；已将 `environment.yml` 改为 `streamlit==1.38.0` 消除环境漂移。2026-08-09 修复。
